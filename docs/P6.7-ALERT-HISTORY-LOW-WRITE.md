# P6.7 低写入告警去重与历史

P6.7 不接入邮件、Telegram、企业微信或其他外部通知，不为告警功能增加任何
Cloudflare KV 写入。

## 存储策略

告警历史复用控制面现有的 D1 数据库。`alert_incidents` 按 `kind + source_id`
建立唯一记录，不保存每次 30 秒轮询的快照。

只有以下状态转换会写 D1：

- 告警首次出现；
- 已恢复告警再次出现；
- 一般告警升级为严重告警，或严重程度发生变化；
- 当前告警恢复。

告警保持不变时，控制面只读取现有状态，返回的 `alertStorage.writes` 为 `0`。
详情中的倒计时或分钟数变化不会触发写入。每个告警源只占一行，并通过
`occurrence_count` 累计复发或升级次数，因此历史表不会随着轮询次数线性增长。

控制面明确返回：

```json
{
  "backend": "d1",
  "kvWrites": 0
}
```

## API

- `GET /api/operations/overview`：返回当前告警、最近 50 条事件状态和本次 D1 写入数。
- `GET /api/operations/alerts?status=all&limit=50`：读取事件历史。
- `status` 可使用 `all`、`open` 或 `resolved`。
- `limit` 范围为 1–200。

以上接口都要求管理员 JWT。

## 面板

运营总览的告警中心包含两个视图：

- **当前告警**：严重/一般告警筛选与处理入口；
- **事件历史**：显示开启/恢复状态、首次出现、最后变化和复发/升级次数。

面板显示“D1 状态事件 · KV 写入 0”，用于明确当前持久化策略。外部通知不在
本阶段范围内。
