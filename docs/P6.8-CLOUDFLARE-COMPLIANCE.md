# P6.8.7 Cloudflare 合规与资源门禁

审计日期：2026-07-29。

这是一套工程门禁，不是法律意见。它的目标是让仓库行为和 Cloudflare 当前公开条款保持保守一致，
并确保任何扩容动作都留下可审计、默认拒绝的决策路径。

## 当前结论

Cloudflare 的 [Self-Serve Subscription Agreement](https://www.cloudflare.com/terms/)
第 2.2.1(j) 规定，除非 Cloudflare 明确书面许可，客户不得使用服务提供 VPN 或其他类似代理服务。
[Developer Platform Service-Specific Terms](https://www.cloudflare.com/service-specific-terms-developer-platform/)
还允许 Cloudflare 在请求或存储造成过度负担、影响服务或网络完整性，或涉嫌违反协议时限制或暂停服务。

因此，仅看到 Workers TCP Sockets、WebSocket 或相关 API 在技术上可用，不能推导出本项目的商业化代理形态已获许可。
在获得覆盖具体账号、节点、协议形态和预期流量的书面确认之前，本仓库按“未获许可”处理。

## 现行默认状态

[`infra/compliance-policy.json`](../infra/compliance-policy.json) 的
`writtenPermission.status` 当前是 `pending`。由此产生以下行为：

- `deploy-nodes` 只允许手动触发，并把 `maintenance`（存量原位维护）和 `provision`（新增节点）分开校验；
  控制面发布成功不再自动触发四节点部署。
- `maintenance` 只允许策略清单和控制面 D1 中都已存在，且 node ID、账号别名、Worker 名称和节点域名
  完全匹配的节点。任一身份字段变化都会在 Cloudflare 写操作之前停止。
- `provision` 仍要求书面许可、许可 Secret、有效期和完整拓扑范围全部通过，并且目标不能已经注册。
- 控制面拒绝创建用户、重新启用用户、提高已启用用户的在线/IP/流量额度、注册新节点、发布优选 IP、
  新增/重新启用落地机，以及扩大落地域名范围。
- 控制面允许已登记节点以相同 node ID、账号别名和域名重新注册，用于更新传输路径、能力和心跳时间；
  不允许借此创建节点、换账号或换域名。
- 禁用、删除用户、降低额度、停用/删除/测试落地机、缩小域名范围、清理租约、读取运营数据以及
  部署控制面安全修复仍可执行。
- 现有用户、订阅和节点不会被脚本自动删除或停止；是否继续运行必须由运营者结合 Cloudflare 的答复作出决定。
- 健康检查和优选 IP 定时任务在门禁未通过时安静跳过，不创建 GitHub Issue，不调用 webhook，也不写 KV。
- 真实 Xray/Mihomo/sing-box 兼容测试只保留手动触发，且同样需要通过门禁。

### 存量节点的受限兼容

控制面安全修复会自动发布；四个存量边缘节点只能通过手动 `maintenance` 原位更新，不能自动扩容或
更换身份。为避免升级窗口内意外切断既有鉴权和同步，策略为 `acc1-n1`、`acc1-n2`、`acc2-n1`、
`acc2-n2` 保留临时 HMAC v1 兼容，截止时间固定为 2027-07-29，不随部署顺延。

该兼容只覆盖心跳、UUID 拉取、准入和用量上报四类既有运行接口。v1 不能注册新节点、不能调用其他
控制接口、不能使用查询参数；控制面也只向上述四个节点发送旧版策略失效签名。新节点和所有新部署
代码始终使用 v2。取得书面许可并完成四节点 v2 升级后，应立即删除这项兼容，不必等待截止日期。

## 取得书面许可后的启用步骤

许可必须明确覆盖实际使用，而不是只确认某个 API 可以调用。向 Cloudflare 支持或销售提交的信息至少包括：

- 两个 Cloudflare Account ID、使用的 Worker 和自定义域名；
- VLESS-over-WebSocket 数据通道、统一控制面、订阅分发和终端用户使用方式；
- 是否收费、预计用户数、日请求量、峰值并发和每次请求的子请求数量；
- Worker 到公网目标或 SOCKS5 落地机的出站形态；
- 滥用投诉、停用用户、保存最少审计证据和响应 Cloudflare 通知的流程。

收到明确书面许可后：

1. 将完整答复保存在受控工单或文档系统，不把正文或联系人信息提交到仓库。
2. 选择稳定的许可引用值，例如支持工单编号，并计算 SHA-256。仓库只保存摘要：

   ```bash
   node -e "const c=require('node:crypto');process.stdout.write(c.createHash('sha256').update(process.argv[1]).digest('hex'))" "许可引用值"
   ```

3. 更新 `infra/compliance-policy.json`：

   - `status` 改为 `approved`；
   - 填写 `referenceSha256`、`approvedAt` 和 `expiresAt`；
   - `accountAliases` 和 `nodeIds` 只能填写许可明确覆盖的范围。

4. 在 GitHub Actions Secrets 中新增 `CLOUDFLARE_PROXY_PERMISSION_REF`，值必须与生成摘要时的原始许可引用完全一致。
5. 先手动运行 `compliance-audit`，确认账号具备 `Account Analytics: Read`，没有未声明的旧 `opus8cf-*` Worker，
   且资源预算通过。
6. 部署控制面，使 `COMPLIANCE_PROXY_ALLOWED=1` 生效；新增节点时按单节点手动运行
   `deploy-nodes` 并选择 `operation=provision`。

策略文件和 Secret 缺一不可。门禁不会把 `approved` 当作永久状态：许可到期、策略复核超过 90 天、
节点不在许可范围、Worker 名称与声明拓扑不一致，都会重新失败关闭。

## 资源预算与审计

`compliance-audit` 每周运行一次，也可手动运行。它每个账号执行一次 Workers Scripts 只读列表和一次
GraphQL Workers 指标查询，汇总最近 24 小时：

- 请求数和错误率；
- `cpuTimeP99`；
- 平均每请求子请求数；
- `exceededResources` 调用；
- 已部署但未在策略中声明的 `opus8cf-*` Worker。

当前没有证据证明两个账号购买了 Workers Paid，因此预算按 Workers Free 保守设置：
每账号 24 小时 80,000 请求、错误率 1%、CPU P99 8 ms、平均每请求 10 个子请求。
这只是项目的提前刹车线，不等于 Cloudflare 官方配额或许可。确认实际套餐后可以降低或调整预算，
但不得把预算上调当成获得代理许可。

审计结果只写 GitHub Actions Job Summary 和 Runner 临时文件：

- KV 写入：0
- D1 写入：0
- Analytics Engine 写入：0
- 邮件、Telegram、企业微信、通用 webhook：0

Cloudflare API Token 需要 `Workers Scripts: Read` 和 `Account Analytics: Read`。GraphQL 即使返回 HTTP 200
也可能在 `errors` 中拒绝查询，脚本会将其视为失败。

## 旧入口与影子 Worker

`infra/compliance-policy.json` 是允许存在的 Opus8 Worker 清单。资源审计发现名称以 `opus8cf-`
开头但未声明的 Worker 时会失败，并在 Summary 中列出名称。它不会自动删除 Worker，以免误删仍有业务依赖的入口。

处置顺序：

1. 确认 Worker 的路由、自定义域名、最近调用量和负责人；
2. 若仍有合法依赖，先迁移到唯一控制面；
3. 取消旧路由或自定义域名，再观察；
4. 最后由账号管理员在 Cloudflare 中删除旧 Worker；
5. 不把旧 Worker 改名后继续运行，也不迁移到另一个账号规避处置。

## 投诉与平台通知处置

内部响应目标如下：

1. 收到 Cloudflare 通知或可信滥用投诉后，立即停止新增用户和节点部署。
2. 优先停用受影响用户；若无法定位或 Cloudflare 要求暂停，则停止受影响 Worker/路由。
3. 保存工单、Ray ID、时间、用户 ID、节点 ID、D1 用量和 GitHub Actions 记录。系统继续只保存 HMAC 后的 IP 指纹，
   不为调查临时增加原始公网 IP 采集。
4. 不自动切换账号、域名、Worker 名称或部署后缀。
5. 在 Cloudflare 指定期限内答复；若通知没有期限，内部目标是在 4 小时内确认收到并开始处置。
6. 只有在 Cloudflare 明确允许恢复且门禁策略已同步更新后，才重新启用数据面。
